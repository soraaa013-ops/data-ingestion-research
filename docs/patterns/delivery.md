# 交付模式：把连接位置、读取机制和消费方式分开

依据：[厂商专题](../vendors/index.md)。下表为跨厂商工程分析，不是行业强制规范。

“直连”至少有三个含义：执行器通过驱动连接数据库；连接生产主库；用户提交任意查询。前者是常见技术，后两者需要分别评估。CDC 也可能连接生产主库，API 背后也可能扫描同一张表。

| 模式 | 选用条件 | 不适合或升级信号 | 源影响与下游代价 |
|---|---|---|---|
| 主库受控批查询 | 有限范围、索引、负载余量，时间窗口可控 | 长扫描、交互式任意 SQL、无法及时取消 | 无额外副本，但要约束扫描和并发 |
| 专用只读副本 | 读多、可接受延迟、可承担副本成本 | 必须读最新提交、复制已滞后、备用节点承担 HA | 转移查询负载，不消除复制成本 |
| 快照/导出 | 低频大范围、固定截面 | 源不支持、导出过慢、筛选能力不足 | 分开衡量快照生成与导出成本 |
| 水位增量 | 可靠增量列、最新状态即可 | 物理删除、漏更时间戳、复杂跨表历史 | 减少重复扫描，但需对账 |
| 日志 CDC | 频繁增删改、需要持续状态 | 无日志权限、低频小任务、团队不具备恢复能力 | 初始化仍扫描，持续运行与物化有成本 |
| 业务 API/文件推送 | 业务语义明确、现成接口 | 逐条 API、大量回源、无一致性保证 | 可封装权限，不天然降低数据库负载 |

## 选择流程

先定义要的是“某时刻状态”还是“事件历史”。再判断时效/删除/更新要求；最后选择来源隔离。比如周期微调需要状态，不必为了 CDC 而保存全部历史；但训练事件序列时定时查询可能丢失中间变化。

先使用已有稳定交付面。若只有主库，小范围查询可以进入验证候选；如果预算无法明确或执行不可控，改为专用副本/导出。需要频繁增量且水位不能覆盖删除时，评估 CDC。

不提供统一“多少行以上必须 CDC”的阈值：行宽、索引、变更率、查询计划和源业务负载都影响结论。

## 模式不是产品采购结果

AWS DMS、Datastream、DataWorks、CDM、Lakeflow 都有自己的来源/目标约束。抽象模式可迁移，具体服务兼容性不可推定。对象存储作为领域中转即可，不要求统一湖仓。
