# 正确性与恢复：从“上传成功”到“可训练”

事实依据：[Google 事件交付](../vendors/google.md)、[Microsoft 水位与删除](../vendors/microsoft.md)、[AWS 文件语义](../vendors/aws.md)。以下为平台设计要求。

## 三种不同的数据语义

- 查询结果：某次或多次查询读到的行，未必是跨表同一时刻。
- 变更日志：带操作及顺序信息的事件，需要去重、合并、删除处理。
- Dataset 版本：用于训练的固定样本集合，有来源、转换规则和完整性声明。

三者不能共用“CSV/JSON 已上传”作为完成定义。

## 故障分析

| 边界 | 可能出错 | 处理与验证 |
|---|---|---|
| 初始快照 → 增量 | 缺口或重叠 | 记录快照/日志边界；按源协议去重，不自行拼接时间 |
| 写文件 → 推进游标 | 游标先成功导致永久漏数 | 持久化及校验后提交检查点；重放必须幂等 |
| 水位相等/迟提交 | 边界漏数 | 稳定次序与回读窗口，按主键合并；窗口仍需明确延迟假设 |
| 源删除 | 旧副本继续存在 | tombstone/CDC 或周期对账；不支持则显式说明 |
| DDL/类型变化 | 静默截断或错列 | schema 版本、兼容检查，不兼容批次隔离 |
| 跨表抽取 | 标签与正文不在同一版本 | 事务截面、业务版本号或明确弱一致性 |
| 发布中途失败 | 训练看到部分数据 | 只有 READY manifest 可发现；禁止按目录列举消费 |
| 日志过期 | 无法从检查点恢复 | 检测并重建基线；不能静默跳到最新 |

## 发布协议建议

每次运行分配 run_id；临时输出按运行隔离。检查文件校验和、数量、schema 和授权后，在目录服务中一次提交不可变 manifest 引用。OBS/S3 多对象上传不应被描述为一个原子事务，原子性由发布记录实现。

“exactly once”应拆成输入交付、处理、目标可见性三个范围。可采用至少一次读取 + 幂等处理 + 单次发布，而不宣称所有系统天然端到端恰好一次。

## ML 特有检查

同一业务实体/会话跨训练评测集会泄漏；去重不能只按文件名；正文与标签要版本对应。固定源快照并不保证样本质量，转换代码、过滤与采样也应版本化。
