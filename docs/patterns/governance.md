# 授权与生命周期：嵌入数据交付

状态：本平台设计建议 P。厂商治理产品专项证据尚不足，见 R05；不将以下内容称为已验证的法律合规方案。

## 区分三个授权问题

1. 执行器可连接哪个系统？
2. 哪个使用者可以复制哪些数据到哪个空间？
3. 复制的数据可以用于什么训练用途，何时到期？

共享只读账号只回答部分第一个问题。管理员具备配置能力，不等于拥有源数据用途审批权。

## 最小对象模型

| 对象 | 关键字段 | 执行时作用 |
|---|---|---|
| SourceConnection | endpoint、secret_ref、engine、owner、budget | 连接及源级限额 |
| DataGrant | principal、objects、columns、row_scope、purpose、expiry、destination | 校验最终导入范围 |
| ImportSpec | source、grant、query/strategy、schedule、schema | 固化用户意图与执行计划 |
| DatasetManifest | source_position、grant_version、transform_version、files、retention | 追溯与生命周期 |

字段只是建议，不要求上来建设大型数据目录。

## 决策流程

数据负责人批准范围和用途，系统负责人确认源侧容量；可将稳定低风险组合预授权一段时间。平台每次执行检查授权仍有效，发布前再次检查撤销状态。空间管理员管理空间及连接配置，不默认替代两类负责人。

必要字段尽早筛选；脱敏若在平台内完成，原始暂存区也必须受控。只保护最终 dataset 而开放暂存文件是明显缺口。审计记录标识和决策，避免记录凭据与完整敏感样本。

## 撤销不是一个开关

撤销后需要停止新任务、处理正在运行任务、阻止发布、限制已发布版本并触发生命周期动作。对象版本、缓存和备份需明确处理范围；已训练模型需要依赖追溯与单独影响评估。

待深化：各厂商源行列策略是否在复制时落实、跨平台身份映射、策略变化与已复制对象之间的同步。没有证据时不能声称自动继承。
