# 10｜把研究变成你的平台方案：三条交付路径共用一个出口

已知平台有 dataset、OBS/S3、Kubernetes Job 和 DSL。未知的是实际规模、频率、版本和已有企业中台。因此这里给出条件化架构，不假设所有部门都要走同一条路。

## 路径 A：领域按需取数，先把现有批量方式做完整

适用：只需周期性固定数据集，获准范围可控，没有必须捕获全部变化的需求。

```text
用户选择获准来源与范围
  → 平台解析 DSL、确认来源能力
  → 按同一数据库的总预算排队
  → Job 从批准的主库/副本/导出入口读取
  → 本次运行的 OBS 暂存
  → 清洗、验证、发布 dataset
```

**用户例子**：售后选择“已关闭问答”，增加日期条件，预览经过同样授权与预算限制的少量内容，看到预计处理范围及任务状态，成功后得到 dataset v8。

平台内部要把 secret_ref、数据授权、抽取策略与脚本参数分开。DSL 应作为结构化输入传给连接器，不把用户字符串拼进 shell 或 Python 源码。SELECT 检查不是脚本注入和数据库权限的共同解决方案。

可保留现有执行器，但应统一任务合同：输入范围、输出位置、检查点、状态、取消、错误分类。批次成功只发布一次；失败不暴露半成品。

## 路径 B：多团队持续使用同源数据，共享一条复制链路

适用：工单长期修订和删除，多消费者重复取数，持续同步收益足够。

```text
业务库 → 成熟捕获器 → 领域中间数据
                         ├→ 售后问答 dataset
                         ├→ 获准的评测 dataset
                         └→ 其他获准分析
```

捕获器可以是托管服务或自建框架，运行可以持续也可以周期性，但需覆盖日志窗口。原始事件到当前表由某个组件明确负责。不要让每个训练用户独立启动一条全库 CDC，重复消耗源端资源。

**用户例子**：用户不再提交针对主库的任意长查询，而是在已授权的领域数据上选择字段和条件；平台记录这次样本对应哪个一致性边界。DSL 可以保留在消费侧。

这是共享基础设施，不意味着所有用户共享同一授权。原始缓冲的可见性应比派生 dataset 更严格。

## 路径 C：企业已有湖仓或数据中台，复用它的第一跳

适用：已有维护良好的表、更新延迟满足要求、权限路径明确。

```text
IT 系统 → 企业已有 ingestion → 湖仓的获准数据
                                    → ML 导入/导出任务
                                    → OBS 固定训练版本
```

避免 ML 团队为相同数据再连一次业务库。需要确认读的是物化副本还是联邦查询：后者仍可能回源。也要确认拿到的是正确当前状态，还是原始事件/软删除历史表。

**用户例子**：从受控表生成售后问答，而不是让用户获取湖底所有文件的凭据。固定导出版本便于训练复现；是否保留额外副本取决于访问、性能和复现要求。

## 业务系统推送是这三条路径都可以接纳的入口

业务提供批量 API、文件或 outbox 时，通过同一交付合同进入平台即可。它不需要被强行伪装成数据库连接器。schema、范围、幂等批次和删除语义仍然明确。

## 一个建议的任务合同

以下是自拟例子，字段名不是任何厂商 API：

```yaml
import:
  source_ref: support-tickets-readonly
  grant_ref: support-qa-training
  strategy: bounded_query
  selection:
    template: closed-ticket-qa
    parameters:
      from: "2026-11-01"
      until: "2026-11-08"
  destination_ref: support-dataset-staging
  consistency: source-declared
  publish: after-validation
```

source-declared 不是一种神奇一致性等级，它表示必须由来源合同给出实际保证；缺失时拒绝宣称严格快照。模板和授权需要绑定最终表达式，不能让用户用未检查的自定义 SQL 覆盖它们。

## 失败后用户应该看到什么？

- “等待源端容量”与“执行失败”分开。
- “文件已写入，校验失败”不能显示“dataset 已完成”。
- “日志恢复点过期，需要重新初始化”不能只显示“重试中”。
- “授权已撤销，停止发布”不需要向用户暴露账号密码或敏感查询结果。

## 优先改造顺序

先补路径 A 的范围授权、执行预算、参数隔离、取消、恢复和发布；再按实际来源引入副本/快照；确需持续变化时增加路径 B；已有可信中台时优先评估路径 C。

无需为了迁移采集器而改写 dataset 消费协议。把获取方式做成可替换模块，把用户可见的训练版本保持稳定，是本轮研究对现有实现最重要的建议。
