# 汇总：生产系统到 ML 消费的阶段性结论

本报告汇总专题，证据和推理保留在各文档。当前是公开资料研究与设计建议，不是产品实测或采购定案。

## 主要结论

1. **不存在从本轮证据可推出的“一律禁止连接生产数据库”规则。** [Microsoft](../docs/vendors/microsoft.md)、[阿里云](../docs/vendors/alibaba.md)、[Databricks](../docs/vendors/databricks.md)均有查询路径。但能力存在不能替代源容量评估。
2. **查询、CDC、快照是条件不同的选择。** [模式比较](../docs/patterns/delivery.md)将机制与主库/副本位置分开；CDC 同样有初始化、日志与持续运维成本。
3. **目前架构可渐进完善。** [场景匹配](../docs/scenario/fit.md)建议保留 DSL、Kubernetes Job、OBS，补源预算、授权绑定、正确性及发布边界。
4. **ML 消费需要独立的数据构建层。** [正确性分析](../docs/patterns/correctness.md)区分原始查询结果、事件日志、可训练版本；文件上传成功不是终点。
5. **数据准入是必要能力，但不是项目唯一目的。** [治理专题](../docs/patterns/governance.md)把连接权、复制范围与用途分开，嵌入获取和消费流程。

## 对架构师两项质疑的回答

生产影响：质疑风险合理，绝对禁止不由当前公开资料支持。应将要求转换为可验证的业务延迟/资源/故障恢复约束，再选择隔离与抽取方式。没有负载证据时也不能反过来声称现有直连已安全。

数据授权：共享账号加空间角色不足以表达训练用途与数据范围。建议增加独立 DataGrant，执行前和发布前检查；复制后生命周期单独管理。具体法律适用及厂商治理能力仍需专门证据。

## 对本场景的推荐方向

默认候选为按需批量 + 来源能力适配 + OBS 运行暂存 + 样本构建 + 不可变 dataset。主库查询是否采用由源预算和取消能力决定；大范围重复抽取优先评估副本/快照；持续修订/删除且批量不足时引入 CDC。

完整路径及演进见[参考架构](../docs/scenario/architecture.md)。这不是要求所有领域采用同一种来源策略，也不要求先建设统一数据湖。

## 哪些认识在深入研究后更明确

- [Databricks](../docs/vendors/databricks.md)同时有持续采集与定时查询：训练频率和采集连续性应分别建模。
- [DataWorks](../docs/vendors/alibaba.md)自定义 SQL 参数优先级提示：授权必须校验最终表达式，不能只检查 UI 过滤项。
- [Google](../docs/vendors/google.md)对象存储输出仍有重复和乱序：不能直接把 CDC 文件当训练快照。
- [华为](../docs/vendors/huawei.md)来源覆盖接近现有栈，但逐连接器分析仍不充分，不应提前宣称最适配。

## 尚未解决

来源精确版本兼容、华为逐连接器限制、厂商治理跨平台边界、独立集成产品对照、量化成本及负载实测。下一步按[任务表](../research/tasks.md)逐项深化，按[验证计划](../docs/scenario/validation.md)将方案转为可测假设。
